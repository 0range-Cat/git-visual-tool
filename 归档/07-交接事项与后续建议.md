## 2. 接手第一周建议动作

1. **跑起来**（冒烟，约 10 分钟）：
   - 确认装了 Python 3.6+ 与 Git for Windows；
   - `python -m py_compile git_visual_tool.py`（语法自检）；
   - 双击 `启动Git工具.bat`，在临时目录建个测试仓库，走一遍：配置身份 → 查看状态 → 暂存全部 → 提交 → 提交历史；
   - （可选）试一个危险按钮看确认框、试自定义命令 `log --oneline -5`、试一次克隆看进度条。
2. **读文档**：先 `归档/00-归档总览.md`，再 `03-技术架构`（改码前必读），排错时查 `06-踩坑经验`。
3. **确认运行环境差异**：作者环境是 Windows 11 + Python 3.13.9 + Git 2.53（Git Bash 生态）；若你的环境不同，重点验证启动 bat（假 python 检测）和凭据管理器登录。

## 5. 后续开发方向建议（按性价比排序，供参考非承诺）

1. **补一套可入库的自动化测试**——v1.3 的 14 项回归是临时脚本没保留，而本项目历史上"测试脚本自身写错"的坑值得用持久化测试防住。建议沿用当时的思路：临时目录 + `GIT_CONFIG_GLOBAL` 隔离 + 真实 git 命令断言。
2. **日志/配置迁到用户目录**——解决"只读目录写不进"的已知限制（改动点：`LOG_FILE`/`CONFIG_FILE` 常量 + `_log_line` 的静默失败提醒）。
3. **失败诊断模式扩充**——`_fail_hint()` 是纯模式匹配，新增场景成本低、收益直接（新手工具的核心价值所在）。
4. **打包分发**——pyinstaller 打 exe 或写一份"免配置环境"安装说明；零第三方依赖是本项目的分发优势。
5. **拆模块**——仅当代码量继续增长才考虑（v1.3 审计判定单文件是有意的分发设计，拆分建议见 03 文档第 5 节）。
6. **国际化**——目前全中文、面向中文新手；若要面向更广人群再做 i18n。
