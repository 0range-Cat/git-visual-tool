## 2. 接手第一周动作清单（建议顺序，总计约 1 小时）

1. **环境确认**（5 分钟）：`python --version`（需 3.6+）与 `git --version` 可用；Windows 上注意"假 python"（商店占位程序）。
2. **语法自检**（1 分钟）：`python -m py_compile git_visual_tool.py`，退出码应为 0（归档时实测通过）。
3. **启动**（1 分钟）：双击 `启动Git工具.bat`（或 `python git_visual_tool.py`）。观察：标题栏应显示 "Git 可视化工具 v1.3"；终端区出现 Git 版本与欢迎信息；若未配置过 Git 身份，应有黄色提醒。
4. **核心链路冒烟**（10 分钟）：在临时目录建一个测试文件夹并选中 →【初始化仓库】→（若从未配置）【配置身份】→ 新建 `a.txt` →【查看状态】应列出未跟踪文件 →【暂存全部】→【提交】写说明 →【提交历史】应看到 1 条记录。
5. **诊断与保护机制抽查**（10 分钟，可选但推荐）：
   - 在一个**非仓库**文件夹点【查看分支】→ 应弹"还不是 Git 仓库"提示；
   - 终端输入自定义命令 `log --oneline -5`（省略 git 前缀）→ 应正常执行；
   - 点【回退(彻底丢弃)】→ 应弹危险确认框（取消即可）；
   - 有命令运行时点右上角关闭 → 应弹"退出会终止命令"确认（选否应留在界面）。
6. **通读文档**（30 分钟）：`归档/00` → `归档/03`（改码前必读）→ 需要时查 `归档/06`（排错对照）。

## 5. 后续开发方向建议（按性价比排序，供参考非承诺）

1. **补一套可入库的自动化测试**（性价比最高）。
   背景：v1.3 的 14 项回归是临时脚本没保留，而历史上"测试脚本自身写错"坑过两回。
   重建思路（沿用当时已验证的方法）：Python `unittest`/pytest + 临时目录建真实 git 仓库 + `GIT_CONFIG_GLOBAL` 指向临时文件隔离全局配置 + 真实 git 命令断言 stderr 关键词（9 类诊断逐一喂真实报文）。GitExecutor 与工具函数是 UI 无关的，可直接单测。
2. **日志/配置迁用户目录**：解决已知限制 #3（只读目录静默丢日志）。改动集中（两个常量 + 一处提醒），风险低。
3. **失败诊断模式扩充**：`_fail_hint()` 是纯模式匹配，新增一类 = 一个 if + 真实 stderr 样本。新手工具的核心价值就在这，持续补充收益直接。
4. **打包分发**：pyinstaller 出 exe（方法已在内置 FAQ），或写"免配置环境"安装说明；零第三方依赖是现成的分发卖点。
5. **拆模块 / i18n / 协作特性**：仅当分发策略或用户群变化才考虑——单文件+中文是刻意的设计决策（见 03 文档 §10 决策 #9），拆分前先想清楚"拷一个文件就能用"这个卖点要不要保。
