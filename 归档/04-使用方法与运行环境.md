# 04 · 使用方法与运行环境

## 1. 环境要求

| 项 | 要求 | 说明 |
|----|------|------|
| 操作系统 | Windows（推荐） | 代码本身跨平台（tkinter + subprocess），但启动器和凭据管理器相关体验按 Windows 设计 |
| Python | 3.6 及以上 | 只用标准库（tkinter/subprocess/queue/threading/json/re/shlex），**无需 pip 安装任何东西**；Windows 安装时勾选 "Add Python to PATH" |
| Git | Git for Windows | 下载：https://git-scm.com/download/win ；保持默认选项安装（自带凭据管理器） |

注意：`where python` 找到的第一个结果可能是微软商店的占位程序（假 python，运行只会弹商店）——启动 bat 已做"真的能跑"验证并自动回退到 `py` 启动器。

## 2. 启动方式

- **推荐**：双击 `启动Git工具.bat`（自动切 UTF-8、定位到工具目录、验证 python 可用、失败时暂停窗口显示报错而不闪退）。
- **等价命令行**：`python git_visual_tool.py`。
- **打包成 exe**（可选）：`pip install pyinstaller` 后执行 `pyinstaller -F -w git_visual_tool.py`，在 `dist/` 得到单文件 exe。

运行时会在工具目录生成两个文件（已列入 `.gitignore`，不入库）：
- `git_tool.log`——全部操作日志（可在【历史日志】页查看/清空/用记事本打开）；
- `git_tool_config.json`——记住上次使用的仓库路径。

## 3. 界面速览

- **顶栏**：仓库路径输入框（可直接粘贴，支持带引号的"复制文件地址"格式）+ 浏览… + 刷新状态；右侧显示 git 版本。
- **左侧**：37 个功能按钮，按 7 组分区（仓库操作/查看/暂存与提交/分支/远程同步/撤销与回退/储藏与标签），鼠标悬停显示"作用 + 对应命令"。
- **右侧**：命令预览行（将要执行的真实命令）→ 进度条 → 深色终端区（黄色=命令、白色=输出、红色=错误、绿色=结果、蓝色=功能说明；右键菜单：复制/全选/清屏）→ 底部 `git >` 自定义命令输入框（可省略 git 前缀，自动补上）。
- **底部状态栏**：仓库位置、当前分支、变更文件数、上次命令结果。
- **三个页签**：操作 / 历史日志 / 使用说明（内置完整教程）。

## 4. 第一次使用（3 步）

1. 双击 `启动Git工具.bat`。
2. 点【配置身份】（仓库操作组），填姓名和邮箱——**只需一次，全局生效**。不配置的话所有提交必定失败（工具启动时也会提醒，提交失败时也会弹窗引导）。
3. 顶部选一个项目文件夹 →【初始化仓库】（或选已有仓库目录）。

## 5. 日常流程（最常用路径）

```
每天开始：【拉取合并 pull】同步远程
改完代码：【查看状态】→【查看改动】→【暂存全部】→【提交】（写清楚说明）→【推送】
```

首次推送到远程：先【添加远程】填 GitHub/Gitee 地址，再【推送并关联】（自动建立分支跟踪，之后直接【推送】即可）。登录走 Git for Windows 弹出的凭据窗口（本工具管不了那个窗口；若被杀毒软件拦截需自行放行）。

| 撤销与回退 | 撤销修改 / 取消暂存 / 回退(保留修改) / 回退(保留暂存) / 回退(彻底丢弃) / 反做提交 / 清理未跟踪 |

## 7. 危险操作（有二次确认，后果说清楚）

| 按钮 | 风险 |
|------|------|
| 回退(彻底丢弃) reset --hard | 丢弃目标提交之后的所有提交与未提交修改，无法恢复 |
| 撤销修改 restore | 未提交的工作区改动被丢弃后无法恢复 |
| 清理未跟踪 clean -fd | 删除所有未跟踪文件/目录，无法恢复 |
| 强制推送 push --force-with-lease | 覆盖远程历史（带回滚保护：远程有他人新提交时会拒绝） |
| 修改上次提交 amend | 改写历史；已推送的提交不建议再改 |

安全原则：不确定时先用【查看状态】【查看改动】【提交历史】观察现状；重要操作前可先推送备份。

## 8. 常见问题（速查）

- **提交报 Author identity unknown** → 点【配置身份】。
- **提示不是 git 仓库** → 先【初始化仓库】或选对目录（含 .git 的项目根）。
- **推送要求登录/失败** → 重新执行一次，在弹出的凭据窗口登录；仍失败检查账号权限或改用 SSH 地址。
- **合并冲突 CONFLICT** → 正常现象：打开文件搜 `<<<<<<<`，手动保留内容后【暂存全部】+【提交】。
- **命令卡住** → 点【终止】，按提示处理后重试（工具已禁止 git 在终端等密码，不会无限卡住）。
- **退出码含义** → 0 成功；非 0 失败，终端红色输出即失败原因。
- **日志在哪** → 工具目录 `git_tool.log`；【历史日志】页可查看，过大时只显示末尾 4000 行。

## 9. 已知使用限制

1. Git 凭据登录窗口由 Git for Windows 自带管理器弹出，本工具无法控制；被拦截需自行放行。
2. 工具禁止了 git 终端交互（`GIT_TERMINAL_PROMPT=0`），纯终端方式的登录走不通，必须凭据管理器或 SSH。
3. 日志写在工具目录，放进只读目录（如 Program Files）会写不进去。
4. 进度条百分比仅网络操作（clone/fetch/push/pull）有效，本地操作只显示滚动动画。
5. 界面初始尺寸 1200×760、最小 980×640；高分屏已做 DPI 适配。
