# 04 · 使用方法与运行环境（含完整操作手册）

## 1. 环境要求（逐项说明为什么）

| 项 | 要求 | 原因/说明 |
|----|------|-----------|
| 操作系统 | Windows（推荐 Win10/11） | 启动器是 cmd 批处理；凭据登录依赖 Git for Windows 自带的管理器。代码本身跨平台（tkinter + subprocess），macOS/Linux 可直接 `python git_visual_tool.py`，但无专门测试 |
| Python | 3.6 及以上 | 只用标准库（tkinter/subprocess/queue/threading/json/re/shlex/ctypes），**无需 pip 安装任何第三方包**。作者开发环境是 3.13.9。Windows 安装时必须勾选 "Add Python to PATH" |
| Git | Git for Windows | 下载 https://git-scm.com/download/win ，保持默认选项安装（默认自带凭据管理器 manager-core，首次 push/pull 时弹 GUI 登录窗） |
| 屏幕 | 无要求 | 已做高分屏 DPI 适配（SetProcessDpiAwareness），窗口 1200×760、最小 980×640 |

**"假 python"警示**：`where python` 的第一个结果可能是微软商店占位程序（运行只弹商店）。启动 bat 已内置"真的能跑"验证 + 自动回退 `py` 启动器；如果两个都失败，会给出 Python 与 Git 的官方下载地址并暂停窗口显示（不闪退）。

## 2. 启动方式（三种）

1. **推荐：双击 `启动Git工具.bat`**。它做四件事：切 UTF-8 代码页（中文提示不乱码）→ 切到 bat 所在目录 → 验证 python 真能跑（防假 python，失败回退 `py`）→ 启动程序；程序崩溃时窗口暂停显示报错（不闪退）。
2. **命令行**：`python git_visual_tool.py`（在工具目录下）。
3. **打包 exe（可选）**：`pip install pyinstaller` → `pyinstaller -F -w git_visual_tool.py` → `dist/` 下得到单文件 exe（这个方法也写在工具内置说明的 FAQ 里）。

**运行时生成的文件**（已列入 `.gitignore`，不入库；删掉不影响程序）：
- `git_tool.log`——全部操作日志（含每条命令的目录、命令、输出、退出码、耗时）；
- `git_tool_config.json`——只记一件事：上次使用的仓库路径。

│ 暂存与提交 …   │                                             │
├───────────────┴────────────────────────────────────────────┤
│ 仓库:… 分支:… 变更文件:N                      上次命令结果    │
└───────────────────────────────────────────────────────────┘
  页签：操作 │ 历史日志（可查看/清空/用记事本打开）│ 使用说明

- **仓库路径输入框**：支持直接粘贴资源管理器"复制文件地址"的带引号格式（自动去引号）；回车或失焦即刷新状态；程序记住上次路径。
- **命令预览**：点任何按钮，先把**将要执行的真实命令**亮出来（URL 里的账号密码显示为 `***`）。
- **终止按钮**：强制结束当前命令（长时间无响应时用；运行中其它按钮全部禁用，只留终止）。
- **自定义命令框**：输入任意 git 子命令执行（如 `log --oneline -5`），**可省略 git 前缀自动补上**；引号不配对时按空格拆分并给中文提醒。
- **状态栏**：仓库位置 / 当前分支（HEAD 分离会标注）/ 变更文件数 / 上次命令结果与耗时。
- **历史日志页**：工具目录 `git_tool.log` 的可视化；超过 4000 行只显末尾并标注；可一键用记事本打开或清空（清空有确认）。

## 4. 第一次使用（完整步骤）

1. 双击 `启动Git工具.bat`。若启动时弹"未检测到 Git"，先安装 Git for Windows 再重开。
2. **点【配置身份】**（左侧第一组"仓库操作"），填姓名和邮箱 → 确定。工具会连续执行两条 `git config --global` 命令，终端可见过程。**只需配置一次，全局生效**。（不配置的话所有提交必定失败；就算跳过这步，提交失败时工具也会弹窗引导到这里，启动时终端也会提前提醒。）
3. 顶部选择项目文件夹：
   - 全新项目 → 点【初始化仓库】；
   - 获取别人项目 → 点【克隆仓库】，填地址（完成后会问是否切换到新目录）；
   - 已有仓库 → 直接选中含 `.git` 的目录即可。
4. （要推送到远程时）【添加远程】填 GitHub/Gitee 地址 →【推送并关联】完成首次推送（自动建立分支跟踪）。登录走 Git 弹出的凭据窗口，登录一次后记住。

## 5. 日常流程（最常用路径）

```
每天开始：  【拉取合并 pull】  ← 同步远程最新代码
改完代码：  【查看状态】→【查看改动】（确认改了什么）→【暂存全部】
            →【提交】（说明写清楚这次改了什么）→【推送】
收尾习惯：  【提交历史】图形化确认存档轨迹
```

一次只提交部分文件时用【暂存文件】指定路径（填 `.` 表示当前目录全部）；提交完发现漏了文件且**未推送**时，可暂存后用【修改上次提交】并入。

## 6. 37 个功能按钮逐一说明（命令 · 作用 · 何时用）

> 与工具内置【使用说明】页内容一致（自动联动生成）。⚠ = 有二次确认的危险操作。

### ① 仓库操作
| 按钮 | 命令 | 作用 | 何时使用 |
|------|------|------|---------|
| 初始化仓库 | `git init` | 在所选文件夹创建空仓库 | 项目第一次纳入版本控制 |
| 克隆仓库 | `git clone --progress <地址> [目录]` | 从远程下载完整仓库 | 获取别人项目/换电脑 |
| 添加远程 | `git remote add <名称> <地址>` | 关联远程仓库地址 | init 后要连 GitHub 时 |
| 查看远程 | `git remote -v` | 查看已关联的远程 | 核对地址是否正确 |
| 配置身份 | `git config --global user.name/user.email` | 设置提交者姓名邮箱 | **第一次使用必须先做** |

### ② 查看
| 按钮 | 命令 | 作用 | 何时使用 |
|------|------|------|---------|
| 查看状态 | `git status` | 哪些文件修改/已暂存/未跟踪 | **任何操作前后都建议看** |
| 查看改动 | `git diff` | 工作区相对暂存区的具体改动 | 提交前确认改了什么 |
| 已暂存改动 | `git diff --staged` | 即将随下次提交生效的改动 | 提交前最后确认 |
| 提交历史 | `git log --graph --oneline --decorate --all -n 50` | 图形化最近 50 次提交 | 回顾历史/回退前定位 |
| 提交详情 | `git show <提交号>`（默认 HEAD） | 某次提交改了哪些文件与内容 | 细看某次提交 |

### ③ 暂存与提交
| 按钮 | 命令 | 作用 | 何时使用 |
|------|------|------|---------|
| 暂存全部 | `git add -A` | 所有修改/新增/删除入暂存区 | 全部改动都要提交时（最常用） |
| 暂存文件 | `git add -- <路径>` | 只暂存指定文件 | 部分提交时；`.` 表全部 |
| 提交 | `git commit -m "<说明>"` | 暂存区内容存为一个版本 | 一批修改完成并暂存后 |
| 修改上次提交 | `git commit --amend --no-edit` ⚠ | 暂存改动并入最近提交 | 刚提交发现漏文件且未推送 |

### ④ 分支
| 按钮 | 命令 | 作用 | 何时使用 |
|------|------|------|---------|
| 查看分支 | `git branch -a -v` | 本地/远程全部分支 | 确认有哪些分支、当前在哪 |
| 新建分支 | `git branch <名>` | 创建不切换 | 保留现场备用 |
| 新建并切换 | `git checkout -b <名>` | 创建并切换 | **开发新功能/修 bug 的起点** |
| 切换分支 | `git checkout <名>` | 切到另一分支 | 前建议先提交或储藏 |
| 合并分支 | `git merge <分支>` | 把指定分支成果合入当前 | **先切到目标分支再合并** |
| 删除分支 | `git branch -d <名>` | 删除已合并分支 | 未合并的会被拒删（保护） |

### ⑤ 远程同步（全部带进度）
| 按钮 | 命令 | 作用 | 何时使用 |
|------|------|------|---------|
| 拉取 fetch | `git fetch --all` | 下载远程更新但**不合并** | 先看看远程有什么再决定 |
| 拉取合并 pull | `git pull` | 下载并自动合并 | **每天开始工作/推送之前** |
| 推送 push | `git push` | 本地提交上传远程 | 提交完成想上传时 |
| 推送并关联 | `git push -u origin HEAD` | 推送并建立分支跟踪 | **新分支第一次推送** |
| 强制推送 | `git push --force-with-lease` ⚠ | 本地历史覆盖远程（带回滚保护） | 改写了已推送历史后；先 fetch 确认 |

### ⑥ 撤销与回退
| 按钮 | 命令 | 作用 | 何时使用 |
|------|------|------|---------|
| 撤销修改 | `git restore -- <路径>` ⚠ | 丢弃工作区未暂存修改 | 改砸了想放弃当前修改 |
| 取消暂存 | `git restore --staged -- <路径>` | 移出暂存区（不动文件内容） | add 错了想重挑 |
| 回退(保留修改) | `git reset <提交号>` | 回退提交，修改留在工作区 | 想重新组织提交 |
| 回退(保留暂存) | `git reset --soft <提交号>` | 回退提交，修改留在暂存区 | 合并最近几次提交 |
| 回退(彻底丢弃) | `git reset --hard <提交号>` ⚠⚠ | 内容/暂存/历史一起回退 | **最彻底最危险**；先看提交历史 |
| 反做提交 | `git revert <提交号>` | 新提交抵消指定提交（不改历史） | 撤销已推送提交的**安全首选** |
| 清理未跟踪 | `git clean -fd` ⚠ | 删除所有未跟踪文件/目录 | 想完全干净时；产物应走 .gitignore |

### ⑦ 储藏与标签
| 按钮 | 命令 | 作用 | 何时使用 |
|------|------|------|---------|
| 储藏修改 | `git stash push -u -m "<说明>"` | 当前修改临时收起（含未跟踪文件） | 要切分支但不想带半成品 |
| 恢复储藏 | `git stash pop` | 恢复最近储藏并从列表删除 | 回到现场继续干活 |
| 储藏列表 | `git stash list` | 查看所有储藏记录 | 确认之前存过什么 |
| 标签列表 | `git tag -n` | 所有标签及说明 | 确认有哪些版本号 |
| 新建标签 | `git tag -a <名> -m "<说明>"` | 给当前提交打版本标签 | 发布版本/标记里程碑 |

### 理解 Git 四区域（内置说明页的 ASCII 图，日常撤销操作的地图）

```
工作区（你正在编辑的文件）
    │  git add  ←【暂存全部】/【暂存文件】
暂存区（准备提交的改动清单）
    │  git commit  ←【提交】
本地仓库（历史存档点）
    │  git push  ←【推送】
远程仓库（服务器，供团队共享）
```
撤销类操作分别作用于不同区域：【撤销修改】→工作区，【取消暂存】→暂存区，【回退】→本地提交历史。

## 7. 安全机制说明

1. **危险操作二次确认**：上表 ⚠ 按钮（共 5 个）执行前弹确认框，内容 = 即将执行的命令（打码后）+ 后果说明 + "确定要继续吗？"。`reset --hard` 与 `clean -fd` 的后果描述最重（"无法恢复"）。
2. **强制推送用 `--force-with-lease` 而非 `--force`**：远程在你看不见的时候有别人新提交时会拒绝覆盖——工具在参数层面替新手挡了最危险的坑。
3. **凭据保护**：URL 里的账号令牌在命令预览/终端/日志三处都显示为 `***`（只影响显示，不影响真实执行）。
4. **防卡死**：工具禁止 git 在终端等待输入（不会出现"卡住等密码"）；运行中除【终止】外全部按钮禁用。
5. **防孤儿进程**：有命令在跑时关窗会弹确认，确认后工具先终止命令再退出。
6. **安全原则（写给用户）**：不确定时，先用【查看状态】【查看改动】【提交历史】观察现状再决定；重要操作前可先推送备份。

## 8. 常见问题（FAQ，与内置说明页同步）

| 问题 | 解答 |
|------|------|
| 提交报 `Author identity unknown`？ | 没配置身份。点【配置身份】填姓名邮箱重试；工具也会在失败时自动弹配置窗口 |
| 提示"不是 git 仓库"？ | 先【初始化仓库】，或确认选的是含 `.git` 的项目根目录 |
| 推送失败/要求登录？ | 首次使用在弹出的 Git 凭据窗口登录；仍失败检查账号权限或改用 SSH 地址 |
| 合并冲突（CONFLICT）？ | 正常现象：打开冲突文件搜 `<<<<<<<`，手动保留内容后【暂存全部】+【提交】 |
| 推送被拒（non-fast-forward）？ | 远程有你本地没有的新提交，先【拉取合并 pull】再推送 |
| 命令卡住不动？ | 点【终止】结束它，按提示处理后重试 |
| 退出码是什么？ | 0 成功；非 0 失败，终端红色输出通常就是失败原因 |
| 怎么打包 exe？ | `pip install pyinstaller` 后 `pyinstaller -F -w git_visual_tool.py`，dist 目录得到 exe |

## 9. 已知使用限制（5 条，避免接手者当 bug 修）

1. Git 凭据登录窗口由 Git for Windows 自带管理器弹出，本工具管不了；被杀毒拦截需自行放行。
2. 工具设置 `GIT_TERMINAL_PROMPT=0`（防卡死），代价是纯终端方式的登录走不通，必须凭据管理器或 SSH。
3. 日志固定写在工具目录；放进只读目录（如 Program Files）日志会静默写不进去。
4. 进度条百分比仅对 clone/fetch/push/pull 有效（依赖 git 进度输出）；本地操作只有滚动动画——git 本身的限制。
5. 高分屏已适配但窗口最小 980×640，更小的屏（如 800×600 老设备）不保证可用。
