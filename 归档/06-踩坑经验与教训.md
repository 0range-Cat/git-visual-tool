# 06 · 踩坑经验与教训

> 本文提炼自 `折腾记录.md`（作者亲笔，含完整排查过程，值得原文精读）。按"症状 → 根因 → 解决 → 预防"格式整理，供接手者排错时快速对照。

## 坑 1：提交必定失败——`Author identity unknown`

- **症状**：查看状态、暂存正常，提交报退出码 128，`*** Please tell me who you are.`
- **根因**：Git 要求每次提交记录作者（user.name + user.email），装完 Git 不会自动有；不配置，所有提交必定失败，且报错英文。
- **解决**：`git config --global user.name/user.email`；工具内点【配置身份】。
- **预防/启示**：给新手用的工具不能假设任何前置知识——报错要翻译成人话，缺什么引导补什么。工具层已做：启动预检 + 失败诊断弹窗引导。

## 坑 2：批处理闪退——LF 换行符

- **症状**：双击 bat 黑窗口一闪而过，无报错无弹窗。
- **根因**：cmd.exe 解析批处理**必须 CRLF 换行**；LF 会使括号块解析错乱，报"命令语法不正确"直接退出。
- **解决**：bat 存为 UTF-8 无 BOM + CRLF；结构改为无括号块的 goto 顺序跳转。
- **预防**：仓库已用 `.gitattributes` 锁死 `*.bat text eol=crlf`——**接手者不要删这行**；新写 bat 同样注意。

## 坑 3：`%errorlevel%` 在括号块里失效

- **症状**：python 明明崩了，bat 里的 `if %errorlevel% neq 0 pause` 永远不执行。
- **根因**：cmd 对 `( ... )` 括号块的变量在**整块解析时一次性展开**，拿到的是进入块之前的旧值。
- **解决**：不用括号块，用 `if errorlevel 1`（执行时动态求值）或延迟展开 `!errorlevel!`。
- **预防**：bat 错误处理逻辑放在括号块外面；现启动器结构可直接复制。

## 坑 4：Windows 商店"假 python"

- **症状**：`where python` 有结果但运行只弹应用商店。
- **根因**：微软商店占位程序 `WindowsApps\python.exe` 不是真 Python，"文件存在"检查骗不过它。
- **解决**：bat 先 `python --version >nul 2>nul` 验证"真的能跑"，失败自动回退 `py` 启动器，再不行给出安装指引。
- **预防**：检查能力而非存在性；`if errorlevel 1 goto try_py` 结构已在启动器中。

## 坑 5：关窗后 git 子进程变孤儿

- **症状**：关窗瞬间终止命令，子进程（如 15 秒的网络操作）在后台完整跑完——资源占用且状态不可见。
- **根因**：窗口 destroy 不会终止子进程；且存在竞态——`stop()` 读 `self.proc` 句柄时命令可能还没 Popen 完成，杀空。
- **解决**：关窗前弹确认，确认后 `stop()`（停止请求标志位 + worker 在 Popen 后补杀）再退出。
- **预防**：终止逻辑必须处理"启动瞬间点终止"的竞态；验证要用文件系统证据（比如让子进程写文件看是否跑完），不能只看 UI。

## 坑 6：URL 里的访问令牌明文出现在日志

- **症状**：`https://user:token@github.com/...` 的令牌出现在命令预览、终端、日志文件三处。
- **根因**：显示层直接 `list2cmdline`，没有意识到远程地址可能内嵌凭据。
- **解决**：`mask_secrets()` 正则打码为 `https://***@...`，应用于预览/终端/日志所有显示路径；**真实执行的参数原样**（改执行层会破坏功能）。
- **预防**：任何会"显示用户输入"的地方都要考虑凭据；打码只做显示层、逐处验证不误伤（端口、SCP 地址、普通消息）。

## 坑 7：粘贴"复制文件地址"的带引号路径被拒

- **根因**：资源管理器"复制文件地址"给的是带引号路径，`os.path.isdir` 对含引号路径返回 False。
- **解决**：`norm_path()` 统一剥引号并规整；配置文件也存干净路径。
- **预防**：接受用户输入时考虑 Windows 生态的"粘贴习惯"。

## 坑 8：git 进度输出会"吃掉"终端行

- **根因**：clone/fetch/push 的进度行靠 `\r`（回车不换行）原地刷新，按 `\n` 切行会得到一坨混合输出，进度条也不会动。
- **解决**：`_pump` 按 `\n`/`\r`/`\r\n` 三种分隔符切行；`PROGRESS_RE` 识别进度行只更新进度条、不打印。
- **预防**：解析子进程输出必须考虑 `\r` 刷新行。

## 方法论教训（比坑本身更值钱）

1. **证据先于直觉**：审计前以为"状态栏刷新卡顿"是大问题，实测 5000 文件才 92ms；而从未想过的"关窗孤儿进程"反而最实锤。直觉列清单，实验划清单。
2. **克制也是开发的一部分**：v1.3 审计列了 11 个疑点，只修 5 个——性能疑点全部实测排除，外观瑕疵不动。不为优化而重构正常工作的代码。
3. **自动化验证 > 肉眼**：回归测试 5/11 的"失败"全是测试脚本自身写错——测试脚本也是代码，也要被怀疑。
4. **真人是最好的端到端测试**：弹窗没屏蔽意外弹给真人点完，反而验证了引导流程。你的用户会点到你想不到的地方，哪怕用户就是你自己。
5. **排查三板斧**：语法检查（py_compile）排除代码错 → 隔离环境复现（临时目录 + `GIT_CONFIG_GLOBAL`）→ 字节级检查（od -c）抓格式问题。
