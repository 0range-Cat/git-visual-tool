# 06 · 踩坑经验与教训（完整排查档案）

> 本文提炼自 `折腾记录.md`（作者亲笔原始记录，含每一步排查命令与输出，值得原文精读）。每坑按"症状 → 排查 → 根因 → 解决 → 验证 → 预防"六段整理，供接手者排错时逐条对照。**同类症状出现时先查本文再动手。**

---

## 坑 1：提交必定失败——`Author identity unknown`（v1.1，2026-09-05）

- **症状**：查看状态、暂存正常；点提交报退出码 128，stderr：`*** Please tell me who you are.`。对不会 Git 的人等于死胡同。
- **排查**：① `python -m py_compile` 语法通过（排除代码错）→ ② 临时目录真实仓库自动化冒烟，核心执行器正常（排除执行链路）→ ③ 复现失败翻日志看到报错原文 → ④ `git config --global user.name` 输出为空 → 根因锁定。
- **根因**：Git 要求每次提交记录作者（user.name + user.email）；**装完 Git 不会自动有**，不配置所有提交必定失败，且报错英文。
- **解决**：`git config --global` 配置一次；工具层：新增【配置身份】按钮（两条 config 队列连续执行）+ 6 类失败自动诊断 + 启动预检提醒 + 失败弹窗引导。
- **验证**：`GIT_CONFIG_GLOBAL` 环境变量把全局配置指到临时文件（不污染真实环境），四场景端到端全过（启动警告/失败提示+弹窗/两条命令写入/再次提交成功）。
- **预防/启示**：给新手用的工具不能假设任何前置知识——报错要翻译成人话，缺什么引导补什么。这也是"启动预检"设计的由来：**在失败发生前提醒，而不是失败后解释**。

## 坑 2：双击 bat 闪退——LF 换行符（v1.2，2026-09-05~06）

- **症状**：双击黑窗口一闪而过，无报错无弹窗，像什么都没发生。
- **排查**：① `where python`/`python --version` 正常（排除没装 Python）→ ② **把 bat 输出重定向到文件再跑**，抓到遗言：`命令语法不正确。`，且 8 秒后无 python 进程存活 → ③ `od -c` 查文件头：行尾是 `\n`（LF）而非 `\r\n`（CRLF）。
- **根因**：cmd.exe 解析批处理**必须 CRLF**；LF 会让 `if (...)` 括号块解析错乱，直接报语法错误退出。这个 bat 是类 Unix 工具写的，保存成了 LF。
- **解决**：bat 存为 **UTF-8 无 BOM + CRLF**；结构改为无括号块的 goto 顺序跳转。
- **验证**：字节检查确认 CRLF；实跑 bat 8 秒后 python 进程存活、无报错。
- **预防**：**仓库已用 `.gitattributes` 锁死 `*.bat text eol=crlf`——接手者不要删这行**；在 Windows 上新写 bat 一律检查换行符；"程序一闪而过"类问题第一反应 = 重定向输出抓遗言 + 字节级检查。

## 坑 3：`%errorlevel%` 在括号块里失效（与坑 2 同时发现）

- **症状**：python 明明崩了，bat 里的 `if %errorlevel% neq 0 pause` 永远不执行——闪退时连错误信息都留不下。
- **根因**：cmd 对 `( ... )` 括号块的变量在**整块解析时一次性展开**，`%errorlevel%` 拿到的是进入块**之前**的旧值（解析期展开，非执行期）。
- **解决**：不用括号块；用 `if errorlevel 1`（执行时动态求值）或延迟展开 `!errorlevel!`（需 setlocal enabledelayedexpansion）。
- **验证**：实跑确认程序崩时窗口停留。
- **预防**：bat 的错误处理逻辑放在括号块外面；现启动器的 goto 结构可直接复制给任何新脚本。

## 坑 4：Windows 商店"假 python"（与坑 2 同时发现）

- **症状**：`where python` 有结果，但运行只弹应用商店。
- **根因**：微软商店占位程序 `WindowsApps\python.exe` 不是真 Python；"文件存在"检查骗不过它。
- **解决**：bat 先 `python --version >nul 2>nul` 验证"真的能跑"，失败自动回退 `py` 启动器，再失败给出 Python/Git 官方下载地址并 pause。
- **预防**：**检查能力而非存在性**——任何"检测 XX 是否安装"的逻辑都应实际调用一次验证。

## 坑 5：关窗后 git 子进程变孤儿（v1.3，2026-09-12）

- **症状**：关窗瞬间终止命令，子进程（实验用 15 秒网络操作）在后台**完整跑完**——资源占用、状态不可见、可能产生用户不知道的副作用。
- **排查**：探针 I——父进程退出后观察子进程状态，15 秒后子进程正常结束，孤儿实锤。
- **根因**：窗口 destroy 不会终止子进程（孤儿是 GUI 工具的经典坑）；且修复过程中发现第二层问题——**竞态**：`stop()` 读 `self.proc` 句柄时命令可能还没 `Popen` 完成（句柄为 None），直接 kill 会"杀空"。
- **解决**：关窗前弹确认（"退出会终止该命令"），确认后 `stop()` 再 destroy；`stop()` 改为**停止请求标志位 `_stop_requested`**，worker 在 Popen 完成后检查标志补杀。
- **验证**：三个场景（启动瞬间关窗/运行中关窗/选取消）全部用**文件系统证据**验证——让子进程跑完时写标记文件，看标记在不在，而不是只看 UI。
- **预防**：终止逻辑必须处理"启动瞬间点终止"；子进程类 bug 的验证要用文件系统等外部证据，UI 表现不算数。

## 坑 6：URL 里的访问令牌明文出现在日志（v1.3，2026-09-12）

- **症状**：带凭据的远程地址 `https://user:token@github.com/...` 的令牌**明文**出现在命令预览、终端、日志文件三处。
- **排查**：探针 L——构造带令牌 URL 执行显示路径，grep 日志确认明文存在，泄露证实。
- **根因**：显示层直接 `list2cmdline`，没意识到远程地址可能内嵌凭据。
- **解决**：`mask_secrets()` 正则打码为 `https://***@...`，应用于预览/终端/日志全部三个显示路径；**真实执行的参数原样传给 git**（改执行层会直接破坏功能）。
- **验证**：逐处验证打码生效；反向验证不误伤（含端口的地址、SCP 形态地址、含 `@` 的普通消息）；并确认 git 实际收到的参数未被打码。
- **预防**：任何会"显示用户输入"的地方都要考虑凭据泄露；打码只做显示层且必须验证不误伤。**接手者新增任何显示路径（如新的日志端点）都要过 `display_cmd`/`mask_secrets`。**

## 坑 7：粘贴"复制文件地址"的带引号路径被拒（v1.3，2026-09-12）

- **症状**：从资源管理器"复制文件地址"粘贴路径到仓库路径框，提示"请先选择一个有效的文件夹"。
- **排查**：探针 K——`os.path.isdir('"C:\\my project"')` 返回 False，误判证实。
- **根因**：Windows"复制文件地址"给的是**带英文引号**的路径；直接 `isdir` 失败。
- **解决**：新增 `norm_path()`（strip 空白 → 去首尾双引号 → 去首尾单引号 → 再 strip），所有路径入口（输入框/浏览/配置读取）统一过它；配置文件也存干净路径。
- **预防**：接受用户输入时考虑 Windows 生态的"粘贴习惯"；路径类输入永远先规整再使用。

## 坑 8：git 进度输出会"吃掉"终端行（v1.0 设计期即处理，v1.3 探针 J 确认健康）

- **根因**：clone/fetch/push 的进度行靠 `\r`（回车不换行）原地刷新；只按 `\n` 切行会得到一坨混合输出，进度条也不动。
- **解决**：`_pump` 按 `\n`/`\r\n`/单独 `\r` 三种分隔符切行（`\r` 在缓冲区末尾时多等一块判断是否 `\r\n`）；`PROGRESS_RE` 识别进度行只更新进度条、不打印。
- **验证**：探针 J——离线 bundle 克隆全链路 53 个进度事件 0→100%。
- **预防**：解析子进程输出必须考虑 `\r` 刷新行——这是所有"实时进度"类 GUI 的通用坑。

## 坑 9（方法论级）：回归测试红了，先怀疑测试脚本

- **症状**：v1.3 审计期间回归测试一度 5/11、13/14。
- **排查**：逐个排查后**全部是测试脚本自身的错误**——忘建仓库、用旧状态断言新命令、弹窗补丁把"确认退出"也拦成取消。
- **教训**：测试脚本也是代码，也会写错；红灯先怀疑测试本身再怀疑被测对象。
- **旁证**：某次测试忘打弹窗补丁，真实的"配置身份"引导窗口弹给真人点完、配置成功——意外完成一次真人端到端验证。**你的用户会点到你想不到的地方，哪怕这个用户就是你自己。**

## 方法论总结（比单个坑更值钱的四条，v1.3 审计沉淀）

1. **证据先于直觉。** 审计前以为"状态栏刷新卡顿"是大问题，实验做完 5000 个文件也才 92ms；而从未想过的"关窗孤儿进程"反而最实锤。**直觉负责列清单，实验负责划掉清单。**
2. **克制也是开发的一部分。** 11 个疑点只修 5 个：性能疑点全部实测排除，外观瑕疵一行不动。**证据不支持的时候，忍住不重构，比改代码难多了。**
3. **自动化验证 > 肉眼。** bat 闪退靠输出重定向抓遗言、字节级检查定位；孤儿进程靠文件系统证据确认。"看起来好了"不算好。
4. **排查三板斧（可复用顺序）**：语法/静态检查排除低级错 → 隔离环境复现（临时目录 + `GIT_CONFIG_GLOBAL`，不污染真实环境）→ 字节级检查（`od -c`）抓格式问题。
