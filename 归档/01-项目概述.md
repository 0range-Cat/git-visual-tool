# 01 · 项目概述（背景 · 意义 · 定位）

## 1. 一句话描述

为"知道 Git 重要但不会用"的 Windows 新手打造的单文件可视化 Git 工具：把 Git 操作封装成按钮，点击时**展示真实命令、执行过程与结果**，让用户"边用边学"，同时用中文把所有报错"翻译成人话"。

## 2. 项目背景（为什么做）

项目所有者在 2026 年 9 月前的真实状态：了解 Git 的重要性，但从未学会使用——教程全是黑窗口 + 英文报错，导致不敢操作，只能把项目文件夹存成"最终版"、"最终版2"、"最终版真的不改了"。

2026-09-05，所有者写下一张需求单（原文见 `折腾记录.md` 开头）：

> 我知道 git 是开发时经常需要的一个版本控制工具，但是我不会使用。
> 帮我开发一个 win 端的可视化工具，把 git 的各个功能封装为功能按钮，
> 但需要展示出在点击时执行了什么命令，并给出执行过程和结果。
> 保留日志。执行过程最好也加入进度条。可以在界面中使用终端这样的界面展示内容。
> 这个工具中还要附注使用说明，说明各个功能是做什么用的，应该什么时候进行使用。

## 3. 开发意义

1. **实用意义**：解决"新手第一次提交必然失败（未配置身份）"、"报错全英文看不懂"、"怕把仓库搞坏不敢操作"三个真实痛点。工具不是替代学习，而是**降低学习的恐惧成本**。
2. **教学意义（设计核心）**："命令预览 + 终端回显"是有意的教学设计——按钮是拐杖，命令才是腿。用户每次点击都能看到按钮背后真实执行的 git 命令，用着用着就学会了。
3. **内容意义**：本项目同时是一次"AI 结对开发"实践，产出了一篇博客文章（`博客文章.md`，2026-09-13 发布）和一组小红书推广文案（`文案/`），均已完成。
4. **示范意义**：开发过程严格执行"证据先于直觉"的审计方法（第三轮折腾），形成了一套"先取证、再按收益/风险排序、证据不支持坚决不修"的工作方法，记录在 `折腾记录.md`。

## 4. 目标用户与场景

| 维度 | 说明 |
|------|------|
| 目标用户 | Windows 上装了（或准备装）Python 和 Git、但不会用 Git 命令行的新手 |
| 核心场景 | 个人项目日常版本管理：看状态 → 看改动 → 暂存 → 提交 → 推送 |
| 次要场景 | 克隆他人仓库、分支管理、回退撤销、储藏与标签（按钮均有覆盖） |
| 非目标 | 不替代专业 GUI（如 SourceTree/GitHub Desktop）；不做多人协作流支持；不跨 macOS/Linux 发行专门启动器（代码本身可跨平台运行） |

## 5. 核心设计理念（三条，源自折腾记录）

1. **给新手用的工具，不能假设任何前置知识**——报错必须翻译成人话，缺什么就引导补什么（v1.1 的配置身份引导由此而来）。
2. **命令预览 + 过程回显 = 可视化学习**——用户永远知道按钮背后发生了什么，出了问题也看得懂日志。
3. **危险操作必须过确认，且把后果写清楚**——所有破坏性按钮（reset --hard、clean -fd、force push 等）弹原生确认框，展示"即将执行的命令 + 后果说明"。

## 6. 项目性质说明（对接手者）

- 这是一个**个人学习 + 内容创作**性质的项目，不是商业产品。
- 作者与 AI 结对开发：作者出需求、当第一个用户、做取舍；AI 写代码。
- 项目于 2026-09-21 后进入维护停滞，2026-10-08 归档封存。功能层面已完整覆盖需求单全部条目。
