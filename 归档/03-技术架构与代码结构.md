# 03 · 技术架构与代码结构（逐模块详解）

> 接手者改代码前请通读本文。核心源文件只有一个：`git_visual_tool.py`（v1.3，1357 行，UTF-8 带 BOM 头 `utf-8-sig`）。本文按源文件从上到下的顺序逐模块说明，标注行号（v1.3 现状，改动后会漂移但相对位置稳定）。

## 1. 技术选型与理由

| 项 | 选择 | 理由 | 换掉它的代价 |
|----|------|------|-------------|
| 语言 | Python 3.6+ | 用户环境门槛最低；代码用 `%` 格式化而非 f-string，就是为了兼容 3.6 | 低，但无必要 |
| GUI | tkinter（标准库） | **零第三方依赖**是核心分发卖点——装了 Python 就能跑，不需要 pip | 高：换 PyQt/wxPython 引入依赖，破坏"拷一个文件就能用" |
| Git 调用 | `subprocess.Popen` 直调本机 git | 工具定位是"命令的翻译器"，行为与命令行 100% 一致，不引入 gitpython 之类的库层语义差 | 高：改用 GitPython 会改变报错原文，`_fail_hint` 的全部模式匹配失效 |
| 并发 | 后台线程 + `queue.Queue` + `after(40)` 轮询 | tkinter 单线程模型下最安全的 UI 更新方式 | — |
| 配置 | `git_tool_config.json`（工具目录） | 只存一项（上次仓库路径），无需更重的方案 | — |
| 日志 | `git_tool.log` 追加写 | 纯文本，记事本可开 | — |

**关键环境约束**：执行命令时注入环境变量 `GIT_TERMINAL_PROMPT=0`——禁止 git 在终端等待输入账号密码，保证界面永不"卡死等密码"。代价：纯终端方式的登录走不通，登录必须依赖 Git for Windows 自带的凭据管理器（GUI 弹窗）或 SSH key。

## 4. 工具函数（L52-117，可独立单测）

### `decode_bytes(b)` — 解码
按 **utf-8 → gbk** 顺序尝试解码 git 的字节输出，都失败则 `utf-8/replace` 兜底。存在原因：Windows 下 git 输出可能是 UTF-8（新版本）或 GBK（中文系统旧输出），单编码会乱码（v1.1 修的乱码问题就在这）。

### `mask_secrets(text)` — 凭据打码
正则 `(?<=//)[^/@\s]+:[^/@\s]+(?=@)` 把 URL 里 `user:password@` 的整段替换为 `***`。**只用于显示层**（命令预览、终端回显、日志文件三处），真实执行的参数原样传给 git。

### `display_cmd(args)` — 命令展示
`subprocess.list2cmdline` 把参数列表转回可读命令行（自动处理引号转义），再过 `mask_secrets`。异常时降级为空格 join。

### `build_command(template, values)` — 模板渲染
把命令模板列表里的 `{key}` 占位符替换为用户输入；值为空的占位参数**整段去掉**（实现"可选参数留空则忽略"，如克隆的子目录参数）。必填项的校验由 `ParamDialog` 保证。

### `norm_path(p)` — 路径规整
`strip` 空白 → 去首尾 `"` → 去首尾 `'` → 再 strip。存在原因：资源管理器"复制文件地址"给的是带引号路径，直接 `isdir` 会 False（v1.3 修）。所有用户输入路径的入口（顶部输入框、浏览、配置文件读取）都过这个函数，配置文件也存干净路径。

## 5. class GitExecutor（L118-239）— 命令执行器

与 UI 完全解耦（构造时不依赖任何 tkinter 对象），历史上全部行为都用过临时仓库 + 真实 git 命令做过端到端验证。

### 5.1 状态字段

| 字段 | 含义 |
|------|------|
| `events` | `queue.Queue`，所有事件（UI 侧 `_poll_events` 消费） |
| `running` | 是否有命令在执行（互斥依据） |
| `proc` | 当前 `Popen` 句柄（**可能为 None**——Popen 完成前） |
| `killed` | 本次命令是否被人为终止 |
| `_stop_requested` | 停止请求标志位（v1.3 竞态修复的核心） |

### 5.2 事件协议（7 种）

```
("start", args, cwd)         开始执行（UI 置忙、记录 cwd、清空 _recent_err）
("note", text)               功能说明行（蓝色"【功能】…"）
("cmd", display)             回显命令（预览框 + 终端黄色 + 写日志头）
("out", text)  / ("err", text)  stdout/stderr 行（err 另存入 _recent_err 供诊断）
("progress", pct)            进度百分比（0-100）
("done", code, secs, killed) 结束：退出码/耗时秒/是否被终止
```

### 5.3 关键方法行为

- **`run(cwd, args, note)`**：`running` 时返回 False（互斥）；否则重置标志并起 daemon 线程 `_worker`。
- **`stop()`**：先置 `_stop_requested=True`，再尝试 kill 当前 `proc`。**为什么需要标志位**：v1.3 审计发现的竞态——命令刚启动的一瞬间点终止/关窗，`self.proc` 还是 None，直接 kill 会"杀空"，命令照常跑完变成孤儿。现在 `_worker` 在 `Popen` 完成后检查 `_stop_requested`，为真则补杀。三个场景（启动瞬间关窗/运行中关窗/选取消）都用文件系统证据验证过。
- **`_worker(cwd, args, note)`**（后台线程）：
  1. 依次投递 `start`、`note`、`cmd` 事件；
  2. `Popen(args, cwd, stdout=PIPE, stderr=PIPE, stdin=DEVNULL, env=带GIT_TERMINAL_PROMPT=0, creationflags=CREATE_NO_WINDOW)`；
  3. `FileNotFoundError` → 中文提示"找不到 git 命令…"（含下载地址）+ done(-1)；其他异常 → "启动命令失败：%s" + done(-1)；
  4. 起两个 `_pump` 线程分别泵 stdout/stderr，join 等两个都读完（**不能用只等进程退出的方式**——管道可能还有未读数据）；
  5. `proc.wait()` 拿退出码，投递 `done`，`running=False`。
- **`_pump(stream, kind)`**：4096 字节逐块读，缓冲区内按 `\n` / `\r\n` / 单独 `\r` 三种分隔符切行。**必须处理 `\r`**：git 网络操作的进度行靠 `\r` 原地刷新，只按 `\n` 切会把整坨进度混进输出。边界：`\r` 在缓冲区末尾时多等一块，判断它是不是 `\r\n` 的前半个。
- **`_emit(kind, raw)`**：空行丢弃；命中 `PROGRESS_RE` → 投递 `progress` 事件（钳到 0-100）且**不打印**；否则投递 `out`/`err` 文本行（过 `decode_bytes`）。

## 6. class Tooltip（L240-283）— 悬停提示

纯标准库实现的 Tooltip（tkinter 没有内置）：`<Enter>` 450ms 后显示（`_schedule`），`<Leave>`/`<ButtonPress>` 隐藏。样式：米黄底 `#ffffe0` 系（`#ffffe6`）+ 实线边框 + 微软雅黑 9 号。显示位置：按钮下方 4px、右移 10px。内容 = `what` + `hint` 两行（见 §8）。

## 7. class ParamDialog（L284-354）— 参数对话框

模态（`grab_set` + `transient`）参数输入框。字段定义格式（`_build_actions` 的 `params` 用）：

```python
(显示标签, 键名key, 默认值, 是否必填required, 是否多行multiline)
```

行为细节：
- 必填字段标签带"（必填）"，可选带"（可选，留空则忽略）"——与 `build_command` 的"空值整段去掉"联动；
- 多行字段用 `tk.Text`（52×4，如提交说明），单行用 `ttt.Entry`（宽 54）；
- `<Return>` 触发确定，但**焦点在多行 Text 里时回车是换行不提交**（`_on_enter` 判断 `focus_get` 类型）；
- `<Escape>` 取消；首字段自动聚焦；
- 校验：必填为空 → 黄色警告框"请填写：xx"并停在对话框；
- 静态方法 `ask(parent, title, fields)`：阻塞到窗口关闭，返回 `dict{key: value}`；用户取消返回 **None**（调用方必须判 None）。

实现要点：
- 左侧按钮面板 = `tk.Canvas` + 内嵌 Frame + 竖向 Scrollbar，按钮 2 列网格排布；**滚轮事件用 `bind_all` 但先 `winfo_containing` 判断指针是否在面板内**——否则滚轮会被全局劫持（这是 tkinter Canvas 滚动的经典坑，别改回直接绑定）；同时绑 `<Button-4>/<Button-5>` 兼容 Linux。

- 右键菜单：复制 / 全选 / 清屏。
- 历史日志页：刷新/打开日志文件/清空日志 3 按钮 + 只读 Text；读取超过 **4000 行只显末尾**，右侧显示文件路径与大小。
- 使用说明页：只读 Text + 多级 tag 样式（h1 15pt 粗/h2 蓝色粗/b 粗/cmd 等宽暗红/p 缩进/warn 橙红），内容由 `_build_help_items()` 生成（§8.6）。

### 8.2 `_build_actions()`（L588）★ 37 个按钮的单一数据源

返回 `[(分类名, [动作 dict…]), …]`，7 组 37 个。动作字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `label` | str | 按钮文字 |
| `cmd` | list[str]\|None | 命令模板，占位符 `{key}` 由 `build_command` 替换；**None 表示走自定义 handler**（克隆/配置身份） |
| `hint` | str | 展示用命令形态（如 `git add <路径>`） |
| `what` | str | 作用（Tooltip 第 1 行 + 使用说明页） |
| `when` | str | 何时使用（Tooltip 第 2 行 + 使用说明页） |
| `warn` | str\|None | 危险提示文本；**非空 = 执行前弹 askyesno 确认框**，内容为"即将执行：\<打码命令\> + warn 文本" |
| `params` | list\|None | ParamDialog 字段定义 |
| `need_repo` | bool | True = 执行前校验当前目录是 git 仓库（初始化仓库/克隆/配置身份为 False） |
| `handler` | func\|None | 特殊动作回调（接收 values dict，完全接管执行） |

**加新按钮只需在此加一个 `A(...)` 条目**——按钮网格、Tooltip、使用说明页全部自动联动，无需碰其他任何地方。

### 8.4 执行链路（一次按钮点击的完整生命周期）

```
_do_action(a)                         L819 统一入口
 1│ executor.running? → 终端黄字"有命令正在执行"，return
 2│ _git_ok? → 否则警告"未检测到 Git"
 3│ norm_path(仓库路径) 有效? → 否则警告"请先选择有效文件夹"
 4│ need_repo 且非仓库? → 警告"可先执行【初始化仓库】"
 5│ a.params? → ParamDialog.ask()；None=取消 return
 6│ a.handler? → handler(values) 并 return（克隆/配置身份走这）
 7│ build_command(a.cmd, values) → 空命令 return
 8│ a.warn? → askyesno("危险操作确认", 命令+warn)；否 → "已取消"
 9└ _run(cmd, note=a.what)
_run: 终端空行分隔 → preview_var 显示打码命令 → executor.run() 起 _worker
      → False(已有命令) → 黄字提醒
_worker（后台）: 事件流 start→note→cmd→(out|err|progress)*→done 进队列
_poll_events（主线程，每 40ms）: get_nowait 清空队列 → _handle_event 逐个
_handle_event:
  start → _set_busy(True)：禁用全部 37 按钮+运行按钮，启用终止，进度条 indeterminate
  cmd   → 预览框更新 + 终端黄字"$ …" + 日志写分隔线/时间/目录/命令
  out/err → 终端白/红 + 日志；err 另存 _recent_err
  progress → 进度条 determinate + 值 + "N%"
  done  → _set_busy(False) + _prog_done（闪 100%，800ms 后归零）
    ├ killed → "已手动终止"
    ├ code==0 → 绿字"完成：退出码 0，耗时 N 秒"
    │    └ _cmd_queue 非空? → _run(队列下一条)   ←配置身份两条命令的续跑机制
    └ code!=0 → 红字"失败：退出码 N" → _fail_hint()
    最后 _refresh_status()（状态栏）+ _after_clone()（克隆成功则问切换目录）
```

### 8.5 `_fail_hint()`（L965）— 失败中文诊断引擎（9 类）

输入 = 本次命令累积的 stderr（`_recent_err`），按**包含关系**逐类匹配，命中全部输出（可叠加），并写入日志 `[提示]` 行：

| # | stderr 特征串 | 中文引导要点 |
|---|---|---|
| 1 | `Author identity unknown` / `tell me who you are` | 未配身份→点【配置身份】；**且额外弹窗**"是否现在配置？"→确认后直接打开 ParamDialog 并执行 |
| 2 | `not a git repository` | 先【初始化仓库】或选对目录 |
| 3 | `configured push destination` | 无远程→【添加远程】+【推送并关联】 |
| 4 | `no tracking information` / `no upstream branch` | 无上游→【推送并关联】 |
| 5 | `does not appear to be a git repository` / `Could not read from remote repository` | 远程地址错→【查看远程】核对；可 `git remote remove` 后重加 |
| 6 | `CONFLICT` | 冲突→搜 `<<<<<<<` 手动解决→暂存→提交 |
| 7 | `non-fast-forward` / `rejected` | 远程有新提交→先【拉取合并 pull】 |
| 8 | `could not read Username` / `Authentication fail` / `403` | 登录/权限→重新执行登录；查权限或改 SSH |
| 9 | `nothing to commit` | 无可提交内容（提示级，非失败） |

**扩诊断 = 在 `_fail_hint` 加一个 if**。模式来自 v1.3 审计探针 A/B/C/M 的真实 git 报文，不是凭空写的——新增类别也应先用真实 git 场景抓 stderr 原文再加。

### 8.6 `_build_help_items()`（L1236）— 使用说明页内容

纯数据驱动的富文本组装：`add(tag, text)` 逐行加。七大节：①本工具是什么（四步机制）②快速上手 ③**Git 四区域 ASCII 图**（工作区→add→暂存区→commit→本地仓库→push→远程仓库）④功能按钮详解（**遍历 `_build_actions` 自动生成**，含每按钮的命令/作用/何时/警告）⑤危险操作与安全建议 ⑥常见问题 8 问（含"怎么打包 exe"：`pyinstaller -F -w git_visual_tool.py`）⑦环境要求。
**改按钮定义后说明页自动同步**——这是"单一数据源"设计的另一半收益。

### 8.7 状态维护与持久化

- **`_refresh_status()`（同步，8s 超时）**：跑三条 git 命令刷底部状态栏——`rev-parse --show-toplevel`（判是否仓库）→ `branch --show-current`（空则"HEAD 分离"）→ `status --porcelain`（数变更文件行数）。在启动、路径变化、每条命令 done 后调用。v1.3 审计探针 F 实测 5000 文件仓库三次调用共 92ms，性能无虞。
- **`_startup_check()`（启动后 80ms）**：`git --version` 探测（失败→红色警告+弹窗"请安装 Git for Windows"）；已配置身份则静默，**未配置则黄色提醒**"首次提交会失败…"（`_has_identity()`：`git config --global user.name` 和 `user.email` 都非空才算已配）；最后打欢迎横幅 + 日志路径。
- **配置读写**：`_load_config`（启动时恢复上次仓库路径，不存在则忽略）/`_save_config`（浏览/克隆切换/关窗时保存）。异常全部静默吞（`except Exception: pass`）——配置文件损坏不应阻止启动。
- **`_on_close()`**：`executor.running` 时弹 askyesno"退出会终止命令"（选否 = 取消关闭）；确认后 `executor.stop()`（防孤儿进程）→ `_save_config()` → destroy。

### 8.8 日志三出口

所有命令的完整轨迹自动写 `git_tool.log`：①历史日志页查看（超 4000 行只显末尾）②"打开日志文件"用系统默认程序 ③直接看文件。每条命令的日志块格式：分隔线 → `时间 目录` → `$ 打码命令` → 全部输出行 → `[成功/失败/已终止] 退出码 耗时` → 空行。

## 9. main()（L1325-1357）— 崩溃兜底

1. Windows 下 `SetProcessDpiAwareness(1)` 高分屏防模糊（异常静默）；
2. `App()` + `mainloop()` 包在 try/except：任何启动异常 → 完整 traceback 追加写日志（`[启动失败]` 块）→ 弹 `showerror`（含日志路径与错误末 1200 字符）→ `SystemExit(1)`。
   这是 v1.2"双击闪退连遗言都没有"教训的直接产物——**保证任何情况下错误可见**。
3. 若连弹窗都失败（tkinter 本身坏了），只写日志再退出。

## 10. 关键设计决策速查（改前三思，每条背后都有踩坑史）

| # | 决策 | 理由/教训 |
|---|------|-----------|
| 1 | 凭据打码只在显示层 | 改执行层会破坏功能；显示三处（预览/终端/日志）全覆盖，且验证过不误伤端口/SCP 地址/普通消息 |
| 2 | `*.bat` 强制 CRLF（.gitattributes） | LF 让 cmd 解析错乱闪退（v1.2 教训）；bat 结构用无括号 goto，`%errorlevel%` 不进括号块 |
| 3 | 停止用标志位而非直接 kill | Popen 完成前句柄为 None 会杀空（v1.3 竞态） |
| 4 | `_pump` 按 `\r` 也切行 | git 进度行靠 `\r` 刷新（否则进度条不动、输出成坨） |
| 5 | `GIT_TERMINAL_PROMPT=0` | 界面永不卡死等密码；代价是纯终端登录不可用 |
| 6 | 关窗确认 + 主动 stop | 否则子进程成孤儿继续跑（v1.3 实锤 15 秒） |
| 7 | 单命令互斥 + 执行中禁全部按钮 | 避免并发 git 命令互相踩状态 |
| 8 | 按钮定义 = 数据（`_build_actions`） | 加按钮/改文案零代码分支；说明页自动联动 |
| 9 | 单文件不分包 | 有意的分发设计：拷一个文件+双击 bat 即用。拆模块会破坏这一点，除非接手者改变分发策略（如 pyinstaller），否则不建议拆 |
| 10 | 配置/日志异常静默吞 | 外围 IO 失败不应拖垮主功能（但这意味着只读目录下日志静默丢失——已知限制） |

## 11. 代码层已知限制

1. 终端 Text 行数无上限（实测 2 万行插入 0.85s，审计判定可接受；超长会话理论上有内存增长）。
2. `_refresh_status` 用同步 `subprocess.run(timeout=8)`，极端卡顿的仓库/网络盘会冻 UI 至多 8 秒。
3. 日志无限追加，只在历史日志页显示时截断，文件本身需手动"清空日志"。
4. `Tooltip` 的 `delay` 参数收了没用（固定 450ms）——外观级冗余，审计判定不修。
5. 自定义命令 `shlex.split(posix=(os.name != "nt"))`，Windows 下 posix=False 的拆分规则与 cmd 有细微差异；引号不配对时降级为按空格拆 + 中文提醒。
