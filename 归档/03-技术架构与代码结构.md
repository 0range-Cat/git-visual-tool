# 03 · 技术架构与代码结构

> 对接手者：改代码前请通读本文。核心源文件只有一个：`git_visual_tool.py`（v1.3，1357 行）。

## 1. 技术选型与理由

| 项 | 选择 | 理由 |
|----|------|------|
| 语言/界面 | Python 3.6+ + tkinter（标准库） | 零第三方依赖，装了 Python 就能跑；降低用户安装门槛 |
| Git 调用方式 | `subprocess` 直接调本机 git 命令 | 工具只是"命令的翻译器"，不做任何 git 库层面的封装，行为与命令行完全一致 |
| 并发模型 | 后台线程执行命令 + `queue.Queue` 事件回传 + 主线程 `after(40)` 轮询 | tkinter 单线程模型下安全更新 UI；stdout/stderr 各一个泵线程逐行读取 |
| 配置存储 | `git_tool_config.json`（工具目录） | 只存一件事：上次使用的仓库路径 |
| 日志 | `git_tool.log` 追加写（工具目录） | 每条命令的目录、命令、输出、退出码、耗时全部落盘 |

**关键环境约束**：执行时设置 `GIT_TERMINAL_PROMPT=0`——禁止 git 在终端等待输入账号密码，避免界面"卡死"；代价是纯终端方式的登录走不通，必须依赖 Git for Windows 自带的凭据管理器或 SSH。

## 3. 三个核心机制（接手者必懂）

### 3.1 事件流：按钮点击后发生什么

```
_do_action(a)                       统一入口
  → executor.running 检查（单命令互斥）
  → git 可用/路径有效/是否仓库 三重校验
  → ParamDialog.ask()（若有 params）
  → a.warn 危险确认弹窗（若有 warn 字段）
  → _run(cmd, note)
      → preview_var 显示打码后的命令
      → GitExecutor.run() 起后台线程 _worker
          → Popen(args, cwd, GIT_TERMINAL_PROMPT=0, CREATE_NO_WINDOW)
          → 两个 _pump 线程逐行读 stdout/stderr（按 \n/\r/\r\n 切分，兼容进度行的 \r 刷新）
          → _emit(): 进度行→("progress",pct)，其余→("out"/"err", 行)
      → 事件进 queue.Queue
  → 主线程 _poll_events 每 40ms 取空队列
  → _handle_event(): start→置忙 / cmd→终端+日志 / out|err→终端+日志(错误另存 _recent_err)
    / progress→进度条 / done→结果分类(成功/失败/被终止)→_fail_hint→_refresh_status→_after_clone
```

### 3.2 功能按钮的"单一数据源"：`_build_actions()`

37 个按钮全部以数据形式定义在 `_build_actions()` 返回的列表里（L597 起），每个动作的字段：

| 字段 | 含义 |
|------|------|
| `label` | 按钮文字 |
| `cmd` | 命令模板（如 `["git", "add", "--", "{paths}"]`，占位符由 `build_command()` 替换） |
| `hint` | 展示给用户看的命令形态 |
| `what` / `when` | 作用说明 / 何时使用（Tooltip 和使用说明页都从这里生成） |
| `warn` | 危险提示文本（非空则执行前弹确认框） |
| `params` | 参数对话框定义列表 |
| `need_repo` | 是否要求当前目录是 git 仓库 |
| `handler` | 特殊处理函数（目前只有克隆 `_act_clone` 和配置身份 `_act_identity`） |

**加新按钮 = 在这里加一个 `A(...)` 条目**；使用说明页自动联动，无需另写文档。

### 3.3 失败中文诊断引擎：`_fail_hint()`

任何命令失败（退出码非 0）后，把本次错误输出（`_recent_err`）逐个匹配 9 类模式，命中即在终端输出"失败原因：…请点 XX 按钮…"：

| 错误特征（stderr 匹配） | 中文引导 |
|---|---|
| `Author identity unknown` / `tell me who you are` | 未配身份 → 引导【配置身份】，并**弹窗询问是否现在配置** |
| `not a git repository` | 不是仓库 → 引导【初始化仓库】 |
| `configured push destination` | 无远程 → 引导【添加远程】+【推送并关联】 |
| `no tracking information` / `no upstream branch` | 无上游 → 引导【推送并关联】 |
| `does not appear to be a git repository` / `Could not read from remote repository` | 远程地址错 → 引导【查看远程】 |
| `CONFLICT` | 冲突 → 手动解决 <<<<<<< → 暂存 → 提交 |
| `non-fast-forward` / `rejected` | 远程有新提交 → 先【拉取合并 pull】 |
| `could not read Username` / `Authentication fail` / `403` | 登录/权限 → 重新执行登录或检查权限/SSH |
| `nothing to commit` | 没有可提交内容（提示级） |

## 4. 关键设计决策（含理由，改前三思）

1. **凭据只打码显示层**（`mask_secrets`/`display_cmd`）：命令预览、终端、日志里 `https://user:token@...` 显示为 `https://***@...`；**真实执行的参数原样传给 git**——打码只在展示层做，不能动执行层，否则会破坏功能。
2. **`*.bat` 必须保持 CRLF**（`.gitattributes` 已锁 `*.bat text eol=crlf`）：LF 换行会让 cmd 解析错乱直接闪退（v1.2 的教训）。同理 bat 采用无括号块的 goto 结构，`%errorlevel%` 不放进括号块。
3. **停止请求标志位**（`_stop_requested`）：`stop()` 不能只 kill `self.proc`——Popen 完成前句柄为 None 会杀空（v1.3 修的竞态）。先置标志，worker 在 Popen 后补杀。
4. **`_pump` 按 `\r` 也切行**：git 网络操作的进度行靠 `\r` 原地刷新，必须逐段处理，否则进度条不动。
5. **孤儿进程防护**：`_on_close` 在有命令运行时弹确认，确认后 `stop()` 再 destroy。
6. **单命令互斥**：`executor.running` 期间禁用全部功能按钮和自定义命令行，只留【终止】。
7. **配置身份用 `_cmd_queue`**：user.name + user.email 两条命令排队连续执行，上一条成功自动跑下一条。

## 5. 已知代码层限制

- 单文件 1357 行未拆模块——刻意为之（分发简单：拷一个文件就能用）；拆分建议见 07 文档。
- 终端 Text 行数无上限（实测 2 万行插入 0.85s，审计时判定可接受）。
- 日志文件固定写在工具目录；放进只读目录会写不进去（`_log_line` 静默吞 OSError）。
- 进度百分比仅对 clone/fetch/push/pull 有效（依赖 git 进度输出），本地操作只有滚动动画——git 本身限制。
